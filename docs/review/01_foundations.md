# 무엇을 학습하는 프로젝트인가

입력은 산업 공정의 영상이고 출력은 시간마다 계산한 이상 점수와 경보다. “영상 전체가 정상/이상인지”만 분류하는 것이 아니라 **어느 시점이 이상한지**를 평가한다. 이상 종류의 정답을 맞히는 다중 클래스 분류는 아니다.

정상 영상에서 정상의 모습을 익힌 뒤, 정상 기준에서 벗어난 정도가 크면 이상으로 의심한다. 부품 외관 변화, 잘못된 위치, 진행 흐름 변화 등이 점수에 영향을 줄 수 있지만, 점수가 높다고 반드시 실제 불량이라는 뜻은 아니다. 조명 변화와 추적 실패도 높은 점수를 만들 수 있다.

## 영상인데 왜 이미지 특징을 쓰나

동영상은 순서가 있는 이미지들의 묶음이다. 이 구현은 프레임마다 DINOv2로 숫자 특징을 얻고, 그 **시간적 순서**를 CycleTracker·진행 점수·motion·GRU에 사용한다. 프레임을 추출했다고 이미지 이상 탐지로 바뀐 것은 아니다. 프레임 순서를 없애고 각각 독립 비교하면 시간 모델은 성립하지 않는다.

IPAD는 이미 `training/frames/영상번호/0.jpg, 1.jpg, ...`처럼 프레임으로 제공된다. 학습 전에 MP4를 다시 만드는 작업은 필요 없다. 테스트 정답은 `test_label/001.npy` 같은 배열이다. 0은 정상, 1은 이상이며, **왜 이상인지의 자연어 설명이나 구체적 고장 원인이 이 이진 배열에 들어 있는 것은 아니다.**

## 장면과 공정의 범위

이번 로컬 결과는 R01–R04, S01–S12의 총 16개 장면이다. R01–R16이 아니다. 실제 장면과 합성 장면 결과는 분리해서 읽어야 한다. 팀원 최신 주요 실험은 R01–R04 중심이다.

전체 16개에 같은 알고리즘을 쓰지만 **정상 기준·템플릿·분포·임계값은 장면마다 별도로 추정한다.** “어떤 새 공정에도 추가 데이터 없이 바로 적용”이 검증된 것은 아니다. 범용성은 우선 동일한 학습 절차를 여러 공정에 적용할 수 있다는 의미다. 새로운 공정에는 그 공정의 정상 자료가 필요하다.

## 네 가지 정상 분할과 테스트

로컬 기본 모델의 `split_normal`은 정상 영상 파일 ID를 seed 42로 정렬해 약 55/15/15/15 비율로 나눈다. 실제 영상 수의 반올림 때문에 비율은 조금 다르다.

| 분할 | 사용하는 자료 | 무엇에 사용하는가 | 하면 안 되는 것 |
| --- | --- | --- | --- |
| fit | 정상 | tracker·Fourier 평균·PCA·memory·AE/GRU 학습 | 실제 테스트 이상을 섞어 학습 |
| validation | 정상 | 평균 모델의 규제, neural checkpoint, 공통 경보 비교 | 테스트 평가를 validation이라고 바꿔 부르기 |
| reference | 정상 | 분기 점수의 기준 분포·motion lower-tail·초기 강도 기준 | 이 분할 자체의 낮은 FPR을 일반화 성능으로 주장 |
| threshold | 정상 | 경보 임계값 q99, 정지 기준 q99.5 | 테스트에서 F1 최대가 되는 값을 정해 정상-only 임계값이라고 주장 |
| testing | 정상+이상 | 추론 완료 후 정답을 읽어 평가 | 학습에 안 썼다는 이유로 후보 선택에도 안 썼다고 주장 |

팀원 후속 정상 이동 진단에는 fit/validation/reference/threshold/evaluation의 5분할도 있다. 팀원 최신 체크포인트와 로컬 초기 모델은 분할·confidence 정책·임계값 산정 방식이 모두 같지 않다.

파일 ID가 다르면 분할은 겹치지 않는다. 그러나 파일 두 개가 동일한 원본 촬영의 잘린 구간일 수도 있다. 원본 recording 그룹 정보가 없으므로 촬영 원본까지 독립이라는 것은 확인되지 않았다. 프레임을 무작위로 나눠 인접 프레임이 train/test에 섞이는 방식보다 낫지만, 독립성 검증을 대신하지는 못한다.

## 점수와 경보는 다른 출력이다

**연속 이상 점수**는 의심 정도의 숫자다. **임계값**은 경보를 낼 기준이고 **경보**는 0/1 판단이다. 점수 8이 불량 확률 80%라는 뜻은 아니다.

예를 들어 원래 점수가 정상 5, 이상 7인데 임계값이 4라면 둘 다 경보가 난다. 기준을 6으로 바꾸면 정상은 경보가 없어지고 이상은 남는다. 점수 배열을 그대로 둔 채 경보 기준만 바꾸면 AUROC/AP는 그대로지만 FPR·Recall·F1은 달라진다.

영상마다 점수가 전반적으로 높다면 경보 임계값만 일부 올릴 수 있다. 다만 그 영상이 정말 더 이상해서 점수가 높았던 것이라면 이상을 놓칠 수 있다. 영상별 강도 보정은 이 절충을 다루는 것이지 이상 정답을 알고 자동 보정하는 것이 아니다.

## sampling과 시간 단위

기본 stride 2는 원본 프레임 0, 2, 4, 6…을 관측한다는 뜻이다. 관측 lag 4는 원본 약 8프레임이다. 첫 24개 관측은 원본 약 48프레임 규모이며, 초 단위로 말하려면 실제 FPS를 확인해야 한다.

관측하지 않은 프레임에는 직전 점수를 유지하는 `zero-order hold`를 사용한다. 원본 3번 프레임에는 2번에서 만든 점수가 들어간다. 미래 4번 점수를 섞어 보간하는 것이 아니다. 평가는 sampled 프레임만이 아니라 원본 전체 프레임에서 한다.

R02 일부 영상은 영상 프레임 수와 라벨 수가 맞지 않는다. 임의로 잘라 맞추지 않고 해당 영상의 라벨을 unknown(-1)으로 처리해 지표에서 제외한다. 입력 영상 자체의 추론은 수행한다. 팀원 E17에서는 66개 영상 중 63개가 유효하고, 33,462개 원본 프레임 중 31,550개가 평가에 포함된다.

## 지표를 읽는 방법

| 지표 | 쉬운 뜻 | 계산·주의 |
| --- | --- | --- |
| AUROC | 이상 프레임이 정상보다 높은 점수를 갖는 정도 | 임계값 독립. 정상/이상이 둘 다 있어야 계산 가능 |
| AP | 높은 점수를 보고 찾아낼 때 얼마나 이상에 집중되는가 | precision-recall 요약. 이상 비율이 다르면 비교에 주의 |
| FPR | 정상인데 경보한 프레임 비율 | FP/(FP+TN). 시간당 경보 건수와 다름 |
| Recall | 이상 프레임 중 경보한 비율 | TP/(TP+FN). 낮으면 이상 시간의 상당 부분을 놓침 |
| Precision | 경보 프레임 중 실제 이상 비율 | TP/(TP+FP). 경보가 적다고 무조건 높아지는 것은 아님 |
| F1 | precision과 recall의 균형 | 2TP/(2TP+FP+FN). 모든 지표를 대신하지 못함 |
| Specificity | 정상을 정상으로 판단한 비율 | 1−FPR |
| Balanced accuracy | 정상/이상 클래스별 정답률 평균 | (specificity+recall)/2 |
| Event coverage | 이상 구간에 한 번이라도 경보가 겹친 비율 | 프레임 recall과 다름. 100프레임 이상 중 1프레임만 잡아도 해당 이벤트 탐지 |
| 탐지 지연 | 이상 시작 후 첫 경보까지의 프레임 수 | 미탐 이벤트는 지연값이 없음. 탐지 성공분만의 평균은 과대해석 금지 |

장면 내에서는 해당 장면의 유효 프레임을 합쳐 계산하고, macro는 장면별 지표를 동일 가중치로 평균한다. 16개 장면 평균은 4개 장면 평균과 직접 비교하면 안 된다. 전체 프레임을 한 번에 합치는 micro 평균과도 다르다.
