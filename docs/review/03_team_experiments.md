# 팀원 파이프라인을 구분해서 읽기

## 구성별 차이

| 구성 | 경로 | 잡으려는 문제 | 잠재적 약점 |
| --- | --- | --- | --- |
| A | DINOv2 → pooled PCA/local memory | 정상에 없는 외형·국소 변화 | 정상 공정 단계 차이도 크게 읽을 수 있음 |
| C | DINOv2 → θ → 정상 평균 μ(θ) → 공유 residual space | 현재 위치에 맞지 않는 외형 | θ 오류가 C를 흔들고, 잘못된 confidence gate가 이상을 누를 수 있음 |
| P | DINOv2 → tracker → alignment/innovation/progress | 지연·역행·진행 흐름 차이 | 비슷한 외형의 반복, 추적 상태 영향, 정상 대기와 정지 구분 어려움 |
| CP | C와 P의 보정 점수 max | 조건부 외형과 진행 정보 결합 | P가 정상에서도 활성화되면 오탐 증가 |
| Full | A/C/P의 보정 점수 max | 여러 종류 이상을 넓게 읽기 | 분기가 많아 정상 큰 값도 늘어남. 항상 CP보다 좋은 것은 아님 |

max 결합은 “하나라도 매우 이상하면 읽는다”는 정책이다. 평균 결합보다 국소 이상을 보존할 수 있지만, 불안정한 분기가 전체를 지배할 수도 있다. OR 경보와 max 점수는 관련 있지만 임계값을 각 분기에서 따로 정하느냐에 따라 결과가 달라진다.

## 초기 E0–E5

E0은 데이터 구조·환경·재현 테스트의 기반이다. E1은 R02 로컬 재실행, E2는 R01–R04 확장이다. E3는 조건부 외형과 진행 분기를 켜고 끄는 핵심 ablation, E4는 세부 구성, E5는 seed·stride·오류 사례 비교다.

ablation은 “전체 성능이 좋다”만 보지 않고 한 요소를 제거했을 때 무엇이 바뀌는지 보는 실험이다. 모듈 도입의 당위성을 설명하기 위해 필요하다. 초기 E2의 Full macro AUROC는 78.31%, AP 69.79%였다. R01의 Full FPR 64.25%처럼 오탐이 심한 장면이 있었다. 높은 recall만 강조하면 오경보 문제를 가릴 수 있다.

## 후속 E6–E10

E6는 정상 영상 5분할을 통한 보정 이동 진단이다. 학습 정상과 테스트 정상의 분포 차이, 앞서 발생한 이상이 tracker 상태를 바꾸는 영향 등을 분리해 살펴본다. 정상 reference와 threshold에서 낮은 FPR이 나와도 그것은 보정에 사용한 자료다. 새로운 정상 evaluation 수치가 중요하다.

E7의 실제 cycle 위치 주석은 아직 확보되지 않았다. 사람이 검증한 위치 정확도를 성능으로 제시할 수 없다. 뷰어나 접촉시트를 준비했다는 사실과 주석을 완료했다는 사실은 다르다.

E8은 confidence의 위치 집중도와 template agreement를 분리하고, 학습 fit 가중치와 score gate를 조합해 비교한다. E8B는 phase 대신 연속 위치 조건에서 정상 기준을 검증한다. E9S는 정상 특징을 freeze/reverse/skip 등으로 편집해 진행 이상 반응을 본다. 합성 편집의 시작·끝 경계 때문에 점수가 올라갔는지도 확인해야 한다.

## 통합 E11, 최소 구성 E11B

E11은 동일 기준에서 A/C/P 등 통합 ablation을 진행한다. E11B는 실제로 필요한 최소 구성을 비교한다. C에 P를 넣으면 어떤 실제 이벤트를 추가로 찾고, 어떤 정상 구간에서 새 경보가 생기는지 확인한다.

CP를 넣어 최종 AUROC만 오른다는 스토리는 정확하지 않다. 기존 외형 분기가 놓친 진행 이벤트를 보완할 수 있지만 AP·AUROC·FPR·event coverage가 각각 다른 방향으로 변할 수 있다. 팀원의 해석도 이러한 절충을 공개한다. 팀원 결과를 “전부 개선”으로 요약하면 안 된다.

## E12: phase-conditioned subspace를 정확히 구분

| Arm | 정상 평균 | residual covariance/subspace | 확인하는 질문 |
| --- | --- | --- | --- |
| S0 | 고정 global 평균 | 공유 | cycle 평균이 없는 기준 |
| S1 | 연속 Fourier 평균 | 공유 | 위치별 평균만 바꾸면 충분한가 |
| S2_K4/K8 | 이산 bin 평균 | 공유 | 연속 평균과 단계 평균의 차이 |
| S3_K4/K8 | 연속 평균 | bin별 covariance | 분산 방향도 단계마다 달라야 하는가 |
| S4_K4/K8 | bin 평균 | bin별 covariance | 멘토의 여러 phase 공간에 가까운 구성 |
| S5 | 연속 평균 | covariance 없이 residual MSE | subspace가 필요한가 |

K4/K8은 진행 좌표를 4/8개 bin으로 나눈 것이다. 각 bin이 의미 있는 작업 이름이라는 뜻은 아니다. 정상 수가 적으면 bin별 covariance 추정이 불안정할 수 있다. 25/50/100% fit 비교에서도 tracker/A가 전체 fit에서 동결된 조건은 end-to-end few-shot 전체 파이프라인의 자료 절감 성능이라고 부르면 안 된다.

## E14, E15: 실험 근거와 경보 정책

E14A는 합성 편집 경계와 편집 내부의 반응을 나눠 분석한다. 편집 경계만 잡는 모델을 지속 정지 탐지 모델로 오해하지 않기 위해 필요하다.

E15A는 고정 모델의 오경보 진단이다. E15B0는 C/CP/OR 경보의 손실과 정상 보정 해상도를 분석한다. E15B/C는 정상 보정·결합 정책을 비교한다. 같은 score를 사용해도 frame q99와 window q99는 다른 임계값이다. window FAR은 정상 창에 경보가 한 번이라도 발생한 비율이며 frame FPR과 혼용하면 안 된다.

## E16: 처리 속도

팀원은 RTX PRO 6000 Blackwell Max-Q 96GB, Ryzen 5600X와 지정된 CPU thread 조건에서 JPEG 입력 스트리밍을 측정했다. CP의 stride 1 입력/점수 처리율은 87.36 FPS, stride 2는 입력 166.80 FPS·점수 83.40회/초였다.

이는 우리 RTX 4060 8GB에서의 수치가 아니다. MP4/H.264 decode, 실제 카메라, RTSP, 네트워크 전송, UI 경보까지 포함한 현장 처리율도 아니다. 사용 장비와 입력 조건을 빼고 “실시간 166FPS”라고 쓰면 부정확하다.
